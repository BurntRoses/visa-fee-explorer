# 运行与更新

已发布数据 `2026.11.17-r11`，工作台 `4.5.2`，时间轴2011–2025。

## 在线分享

公开站点：https://burntroses.github.io/visa-fee-explorer/

发布仓库：https://github.com/BurntRoses/visa-fee-explorer

GitHub Pages托管工作台、按需证据、完整JSON及预算内的来源归档，访问者无需登录。Pages体积预算850MiB，较大原件链接至同版本GitHub Release；全部来源另生成确定性ZIP分卷。本地与离线文件保留原件相对路径。发布目录为`deploy/github-pages/site/`，独立Git仓库为`deploy/github-pages/`；本地研究环境和开发依赖不上传。本地版本号与线上发布状态分别记录。实际在线版本与发布文件数以站点`deployment.json`、本地`deploy/deployment-manifest.json`和对应部署报告为准。

更新并完成所需验证后，先准备发布文件：

```sh
.research-venv/bin/python scripts/prepare_github_pages.py
```

脚本生成`deliverables/source-archives-2026.11.17-r11/upload-plan.json`及来源清单，列出Pages内原件、Release原件、全部ZIP分卷、字节数与SHA256；准备阶段只写本地文件。按以下顺序发布：

1. 检查上传计划与清单，确认版本和仓库。
2. 使用计划中的`create_release_command`，将`<PUBLISHED_COMMIT_SHA>`替换为确切发布提交；已有同版本Release时按计划中的上传命令处理。
3. 运行下列检查。脚本实际下载每个计划资产并核对大小与SHA256，全部通过后再推送引用这些资产的Pages。

```sh
.research-venv/bin/python scripts/verify_source_release.py --plan deliverables/source-archives-2026.11.17-r11/upload-plan.json --report docs/validation/source-release-r11.json
```

4. 提交并推送Pages发布目录：

```sh
git -C deploy/github-pages add --all
git -C deploy/github-pages commit -m "Update visa fee explorer"
git -C deploy/github-pages push
```

`main`推送触发`.github/workflows/pages.yml`。Pages部署完成后，用部署检查确认实际产物与五图、下钻、真实导出；涉及国家背景时补查相应序列。流光代码没有变更时复用原有动效证据：

```sh
.research-venv/bin/python scripts/verify_deployment.py --url https://burntroses.github.io/visa-fee-explorer/ --report docs/validation/deployment-live-r11.json
.research-venv/bin/python scripts/verify_country_context_browser.py --url https://burntroses.github.io/visa-fee-explorer/ --report docs/validation/r11-context-live.json
```

## 使用

双击`成果入口.html`或`app/签证这笔钱-离线版.html`。单文件包含程序、样式、索引、路线证据、来源与完整原始观测，不需要安装环境或联网。保留原项目树时可打开来源原件。

环形、单国环形和桑基默认显示付款方到收款方的流光，年份暂停后仍持续。顶部“流光”可独立开关并保存；系统减少动态时暂停。SVG／PNG保存当前静态光痕。

HTTP模式先读取绘图索引，路线分项按需载入；完整观测只在完整JSON导出时解压。索引及归档大小随构建更新，以当前产物为准。在项目根运行：

```sh
.research-venv/bin/python -m http.server 18765 --bind 127.0.0.1
```

打开`http://127.0.0.1:18765/app/`。公开分享使用上方GitHub Pages地址。

## 完整离线复算

```sh
.research-venv/bin/python scripts/rebuild_all.py
```

完整流程读取冻结来源，按`scripts/research_packages.py`注册的44个研究数据包统一提取。金额层运行四个核心模型及扩展包，共27个原币包；背景包独立于金额包。随后统一汇率、生成同一边集合的进出账、余额、矩阵、联合范围、国家摘要、国家背景、索引和单文件。r11完整离线重建已完成；本地验证、打包及发布分别以同版验收报告确认，历史r9报告保留在原路径。研究脚本默认离线，刷新下载需显式参数。

当前模型约定：申根按申请国籍、收款成员及收费生效日期计算有效费率和共同范围；加拿大六项实际收入使用FY2023–24至FY2025–26的`.25/.75`自然年桥接与全国联合范围；韩国、越南已有金额模型，付款来源仍保留UNK。印尼、尼泊尔实收替换旧数量费用情景，CHN／IND明确零费边保留；澳大利亚2025采用两个完整FY的VAC收入各半。印度补入FY2024/25实收后更新2024桥接和2025年度水平代理。冈比亚预算、塞浦路斯官方索引摘录保持身份。原始财政收入、模型金额和来源分配分别保存，项目总科目不加到组成细项上。

首次搭建开发环境需要Python 3.12、`requirements.txt`、Node.js及pnpm，前端依赖采用`app/workbench/pnpm-lock.yaml`：

```sh
python3 -m venv .research-venv
.research-venv/bin/pip install -r requirements.txt
cd app/workbench
pnpm install --frozen-lockfile
pnpm run dev
```

开发默认端口18766；若已占用，以启动日志中的实际地址为准。依赖安装完成后，`build_app.py`直接运行本地TypeScript和Vite，避免构建时自动安装或联网。交付HTML运行不需要这些工具。

## 定向更新

涉及研究原件、精修规则或历史／区域模型时，先运行对应提取脚本并更新原币模型产物；跨包变更使用上方完整复算。统一底稿、核心金额模型与应用的定向重建为：

```sh
.research-venv/bin/python scripts/build_dataset.py
.research-venv/bin/python scripts/build_money_model.py
.research-venv/bin/python scripts/build_app.py
```

`build_money_model.py --reuse-models`只在全部注册的原币模型包均已更新、无需重算核心模型时使用。只修改界面可直接运行`build_app.py`。不要手改生成的`app/assets/`、`app/data/`或离线文件。

## 数据路径

| 路径 | 内容 |
|---|---|
| `data/raw/` | 归档原件，URL与hash在来源登记 |
| `data/research/` | 基础及扩展研究包：来源、规则、观测、覆盖与提取结果 |
| `data/research/evidence_refinement/` | 申根、英国／加拿大、韩国／越南3个精修补包；原件定位、补充规则、观测与核对结果 |
| `data/estimates/*_flows.json` | 全部注册的原币费用模型包、参数、边际／联合范围与期间桥接 |
| `data/processed/flows.json`与CSV | 同一版付款国籍→收款政府的费用分项 |
| `data/processed/country_balances.json` | 国家两侧及差额、未知、边际范围 |
| `data/processed/country_profiles.json` | 全部已建模收付摘要、匹配数量的费用折算、同年人口与来源 |
| `data/processed/coverage_inventory.json` | 250国家／辖区×15年×六类别，历史费率、现价、数量、金额分列 |
| `data/processed/observations.json` | 原始单元格与派生，保留数量指标及期间 |
| `app/data.json` | 同版模型主载荷 |
| `app/workbench/src/` | React/D3源码、状态、共用查询、五种图形 |
| `app/data/index.json` | 轻量绘图索引、覆盖与来源 |
| `app/data/chunks/` | 按目的地和年度压缩的路线依据 |
| `app/data/context/` | 按国家压缩的签证／旅行背景序列，含精确期间、单位、源和上下限状态 |
| `app/data/full-data.json.gz` | 含全部观测的完整导出 |
| `app/legacy-r2/` | 历史界面源文件 |

原期会计账与主边是控制／分配关系，不能重复相加。类别、目的地、国籍和年度缺口在覆盖面板可查；“现价”不作为历史收费已知。
